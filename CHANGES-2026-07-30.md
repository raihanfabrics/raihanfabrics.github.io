# Changes — 2026-07-30

Five new features, in the order requested.

## 1. Receipts (saveable as image)

New "Receipts" tab (next to Record Sale) listing every past sale,
searchable by invoice #, customer name, or phone — each with a Download
button that saves a PNG receipt image. The receipt is drawn directly onto
an HTML canvas (no new npm dependency, works fully offline since this is
a PWA) showing shop name/address, invoice #, date, customer, line items
with SKU, subtotal/discount/total, and payment status.

Right after recording a new sale, there's now also a "Save as Image"
button next to the "Recorded as INV-000123" confirmation, so staff can
hand a customer their receipt on the spot without hunting for it in the
Receipts tab.

No schema changes — built entirely from data you already have
(`sales`, `sale_items`, `fabrics`, and the auto-generated `invoice_number`
you already had).

## 2. Lead time tracking

Suppliers table has a new "Lead time" column showing average days between
placing an order and receiving it, plus a "+ Log order placed today"
button and a "Mark received" button for any order still awaiting
delivery.

**Important scoping note:** this can't be backfilled — there was never a
timestamp anywhere for *when an order was placed* (only `purchased_at`,
which is when goods were received), so lead-time data only starts
accumulating from whenever you start clicking "Log order placed" going
forward. A supplier will show "No data yet" until their first logged
order is also marked received.

Needs a migration: `supabase/schema_v9_supplier_lead_time.sql` (new
`supplier_orders` table — any signed-in staff can log/receive, this isn't
owner-gated the way editing a supplier record is).

## 3. "Haven't ordered in X weeks" nudge

A small badge now appears next to a supplier's name on the Suppliers
table if it's been 4+ weeks since your last purchase from them — built
from the same batch data already loaded there, no new fetch or schema
change. Suppliers you've never ordered from at all don't get this badge
(their "No purchases yet" total already says that more plainly).

## 4. Dead stock report — enhanced

Turned out this already existed on your Dashboard (a simple list of
stock sitting unsold for 90+ days) — upgraded it rather than rebuilding:
- Ranked by actual capital tied up (stock meters × last known cost per
  meter), worst-first, instead of just listing in no particular order.
- Each dead-stock row now shows the ₨ value tied up, not just the meter
  count.
- The "Dead Stock" stat card on the dashboard now shows a total ₨ figure
  for everything currently stuck.

No schema change — uses `stock_batches` data the Dashboard was already
fetching.

## 5. Credit ledger (wholesale accounts)

New "Credit Ledger" tab showing every approved wholesale account's
running balance owed, worst-first. Click "View Ledger" on any account to
see its full transaction history (each unpaid/partial sale as a charge,
each logged payment) and log a new payment (amount, method, notes) right
there.

**How the balance is computed** (matters for interpreting the numbers):
`balance = sum of that account's sale totals where payment_status isn't
'paid'` `− sum of payments logged against the account`. A sale marked
"paid" at the register was never credit, so it's excluded entirely. A
"partial" sale counts for its *full* total (there's no stored record of
how much was actually paid at sale time) — log the amount that actually
came in as a payment, same as any later payment, and the balance nets out
correctly.

**No historical backfill.** If any of your wholesale accounts already
have a real-world balance from before this shipped (unpaid/partial sales
you've been quietly getting paid down in cash), their computed balance
here will look too high until you log a one-time "opening balance
adjustment" payment to true it up. Worth doing per account when this
goes live, if it applies.

Needs a migration: `supabase/schema_v10_credit_ledger.sql` (new
`account_payments` table — any signed-in staff can log a payment, since
they're often the one physically collecting it).
