## 2. WhatsApp send button on receipts

Every row in the Receipts tab (and the confirmation banner right after
recording a sale) now has a "Send via WhatsApp" button — but only when a
customer phone number was actually recorded with that sale. Worth being
upfront about how this actually works, since a plain web app genuinely
can't do what a business-tier WhatsApp integration can:

- On a phone (this being a PWA, that's the normal case), it uses the
  Web Share API: the receipt image is handed to your phone's native
  share sheet, pre-attached — you pick WhatsApp, then pick the contact.
  The web platform doesn't allow a page to auto-select a specific
  WhatsApp contact, only the person using the share sheet can.
- On desktop, or if a browser doesn't support sharing files, it falls
  back to downloading the receipt image and opening the customer's
  WhatsApp Web chat with a short note pre-filled — the image then needs
  to be attached by hand (drag the downloaded file in), two extra taps
  instead of one.

Fully automatic "push this image straight into their chat with zero
taps" would need the paid, approval-gated WhatsApp Business API with a
server component — a real project on its own if you ever want to go
there, but out of scope for what a client-side web app can do.

## 3. Credit Ledger — rebuilt manual, decoupled from sales, WhatsApp balance summary

This is a meaningful redesign from last session's version, per your
feedback:

**(3a) Fully manual.** Every entry is typed in by hand now — pick
"Charge (they borrowed)" or "Payment (they paid back)", an amount, an
optional note, done. The ledger no longer reads from `sales` at all.

**(3c) Recording a sale never touches this.** Whether a sale is marked
paid, partial, or unpaid at the register has zero effect on the credit
ledger — the two systems are now completely separate, exactly as asked.
(This does mean the ledger balance only reflects what's typed in here —
if a wholesale account already had a real balance from the previous
sales-derived version, or from before any of this existed, log an
opening entry to true it up.)

**(3b) "Send Balance" button.** Each account row has a Send Balance
button that opens WhatsApp with the account's own saved number, message
pre-filled with their last (up to) 10 transactions — each line showing
type, amount, and the running balance at that point — ending with the
current total and a request to confirm. Nothing is sent automatically;
staff still has to tap Send in WhatsApp, same one-extra-tap-required
limitation as the receipt button above.

**(3d) Message is in Pashto**, hardcoded — regardless of what language
the staff member viewing the app has it set to, since this message is
read by the buyer, not the staff. Dates are plain Gregorian (no Hijri/
Shamsi conversion, matching the same scope decision made everywhere else
date-related in this app).

**Schema change:** this replaces last session's `account_payments`
design entirely.
- Run `supabase/schema_v11_credit_ledger_manual.sql` — new
  `account_transactions` table (`type`: 'charge' or 'payment').
- **Skip `schema_v10_credit_ledger.sql`** if you haven't run it yet —
  it's now marked superseded at the top of the file. If you already ran
  it, no harm; the `account_payments` table it made is just unused now.

## 4. Suppliers table sorted by rating

sort to the bottom rather than mixing in at the top — a plain descending
